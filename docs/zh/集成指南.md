## 1.2 环境准备与初始化

### 1.2.1 安装依赖

```bash
# A2A-T SDK
pip install a2a-t-sdk

# A2A 官方 Python SDK（根据服务端框架选择 extra）
pip install "a2a-sdk[fastapi]"   # 使用 FastAPI 托管 Agent 服务时
```

环境要求：Python 3.12+（`a2a-t-sdk` 要求）；`a2a-sdk` 要求 Python 3.10+。

> 本指南后续示例使用 `httpx` 演示业务系统侧的 HTTP 请求，`httpx` 不是 `a2a-t-sdk` 的依赖，业务系统可替换为 `requests` 等任意 HTTP 客户端。

### 1.2.2 配置 `.env`

准备 `package_data/.env`（可直接复制 `package_data/env.example`），至少配置：

```properties
A2AT_LANGUAGE=zh-CN
A2AT_PROMPT_SOURCE_TYPE=local_file
A2AT_PROMPT_RESOURCE_LOCAL_ROOT_DIR=
A2AT_PROMPT_COMPLIANCE_ENABLED=true
A2AT_LLM_PROVIDER=deepseek
A2AT_LLM_MODEL=deepseek-chat
A2AT_LLM_API_KEY={your_llm_api_key}
A2AT_LLM_BASE_URL=https://api.deepseek.com
A2AT_NEGOTIATION_STATE_STORE_TYPE=in_memory
```

> `A2AT_LLM_API_KEY` 是**调用外部大模型**使用的密钥，与下文"接口鉴权"中 agent 之间通信的凭证是两回事，请勿混淆。

### 1.2.3 初始化 A2A-T 客户端与服务端

```python
from pathlib import Path

from a2a_t.client.a2at_client import A2ATClient
from a2a_t.server.a2at_server import A2ATServer

client = A2ATClient(env_path=Path("package_data/.env"))
server = A2ATServer(env_path=Path("package_data/.env"))
```

`A2ATClient` 与 `A2ATServer` 均可传入 `env_path`；不传时默认读取 `package_data/.env`。

## 1.3 AgentCard 初始化

### 1.3.1 什么是 AgentCard

AgentCard 是 A2A 协议中描述 agent 元数据的 JSON 文档，声明了 agent 的身份、能力、技能、服务端点与鉴权要求。它通常被发布在 agent 的 `/.well-known/agent-card.json` 路径下，供客户端和注册中心获取。

### 1.3.2 AgentCard 核心字段

| 字段 | 必选 | 说明 |
|--|--|--|
| `name` | 是 | agent 名称 |
| `description` | 是 | agent 能力描述 |
| `url` | 是 | agent 服务端点（A2A 任务请求发送地址） |
| `version` | 是 | AgentCard 版本 |
| `capabilities` | 是 | 能力声明，如 `streaming`、`pushNotifications` |
| `skills` | 否 | agent 提供的技能列表 |
| `securitySchemes` / `security` | 否 | 鉴权方案声明（见 1.6 节） |
| `provider` | 否 | 提供方信息（组织、官网） |
| `defaultInputModes` / `defaultOutputModes` | 否 | 输入输出媒体类型 |

### 1.3.3 声明 A2A-T 能力

A2A-T 是 A2A 协议的电信扩展。建议在 AgentCard 中显式声明 agent 支持 A2A-T，使对端或编排系统能够识别并切换为 A2A-T 交互流程。可通过 `skills` 或自定义扩展字段声明，例如：

```json
{
  "name": "incident-notification-agent",
  "description": "Telecom incident subscription & notification agent (A2A-T).",
  "url": "https://agent.example.com/",
  "version": "1.0.0",
  "capabilities": {
    "streaming": false,
    "pushNotifications": false
  },
  "skills": [
    {
      "id": "a2at.subscribe_incident",
      "name": "Subscribe Incident",
      "description": "A2A-T structured prompt based incident subscription.",
      "tags": ["telecom", "a2a-t"]
    }
  ],
  "securitySchemes": {
    "apiKey": {
      "type": "ApiKey",
      "in": "header",
      "name": "X-API-Key"
    }
  },
  "security": [
    { "apiKey": [] }
  ]
}
```

### 1.3.4 初始化示例（配合 `a2a-sdk`）

使用 A2A 官方 SDK 构造 Agent 时，将上述 AgentCard 声明作为其能力配置。`a2a-t-sdk` 不提供 AgentCard 模型，AgentCard 由 A2A SDK / 业务系统维护，具体字段以 `a2a-sdk` 官方文档为准，例如：

```python
from a2a_sdk.core.agent import Agent, A2AConfig

agent = Agent(
    config=A2AConfig(
        name="incident-notification-agent",
        description="Telecom incident notification agent (A2A-T).",
        url="https://agent.example.com/",
        agent_card_version="1.0.0",
        # capabilities / skills / securitySchemes 按 1.3.3 的声明配置
    ),
    # A2A-T 服务端封装在业务回调中调用，见 1.5.4
)
```

> `a2a-sdk` 的 AgentCard 模型字段名以官方文档为准，本节代码为示意。

## 1.4 AgentCard 注册与检索

### 1.4.1 注册中心（registry-center）概述

注册中心是 A2A 生态中的 agent 目录服务，用于集中注册 AgentCard 并支持按能力/名称检索 agent。A2A-T 的部署中，服务端 agent 启动后向注册中心注册自己的 AgentCard，客户端 agent 通过注册中心发现目标 agent 的端点。

> 当前 `a2a-t-sdk` **不包含**注册中心客户端（见 1.8 节差距分析）。注册与检索通过网络调用注册中心 HTTP API 完成，或由 A2A SDK / 业务系统封装。

### 1.4.2 注册 AgentCard

服务端 agent 完成初始化后，将 AgentCard 发布到注册中心并保持可访问：

```python
import httpx

AGENT_CARD = {...}  # 1.3.3 定义的 AgentCard JSON

def register_agent_card(registry_url: str, agent_card: dict) -> None:
    resp = httpx.post(
        f"{registry_url}/agents/register",
        json=agent_card,
        headers={"Authorization": f"Bearer {REGISTRY_TOKEN}"},
        timeout=10,
    )
    resp.raise_for_status()
```

### 1.4.3 检索 AgentCard

客户端根据目标 agent 名称或技能，从注册中心查询并获取其 AgentCard，从而得到 `url` 与鉴权要求：

```python
import httpx

def discover_agent(registry_url: str, skill: str) -> dict:
    resp = httpx.get(
        f"{registry_url}/agents/discover",
        params={"skill": skill},
        headers={"Authorization": f"Bearer {REGISTRY_TOKEN}"},
        timeout=10,
    )
    resp.raise_for_status()
    return resp.json()
```

### 1.4.4 直接获取 AgentCard

若已知 agent 端点，也可以直接访问其标准路径获取 AgentCard：

```python
import httpx

resp = httpx.get("https://agent.example.com/.well-known/agent-card.json", timeout=10)
agent_card = resp.json()
```

## 1.5 HTTP 请求发送（A2A JSON-RPC）

### 1.5.1 A2A 消息与 JSON-RPC 2.0

A2A 协议基于 HTTP + JSON-RPC 2.0。任务与协商消息以 JSON-RPC 请求发送到 agent `url`，要求：

- 方法：`POST`
- `Content-Type: application/json`
- 请求头携带 A2A 版本：`A2A-Version: 1.0`
- 使用 A2A-T 扩展时，请求头声明扩展 URI：`A2A-Extensions`（见 1.5.2）

### 1.5.2 填充 A2A 请求头与响应头

A2A 协议通过 HTTP Header 传递协议版本与扩展声明。所有 A2A 服务参数均以 `a2a-` 前缀命名（如 `A2A-Version`、`A2A-Extensions`），与传输层参数（如 `Content-Type`）相互独立、可稳定共存。

涉及 A2A-T 的 Header 如下：

| Header | 方向 | 必填 | 取值 |
|--|--|--|--|
| `A2A-Version` | 请求头 | 是 | 协议版本，如 `1.0`（客户端必须随每个请求携带） |
| `A2A-Extensions` | 请求头 | 否（使用扩展时建议） | 逗号分隔的扩展 URI 列表，声明本次请求要使用的扩展 |
| `A2A-Extensions` | 响应头 | 否（使用扩展时建议） | 服务端实际参与的扩展 URI 列表（逗号分隔） |

**请求头填充规则：**

- `A2A-Version`：客户端必须携带，值为 `1.0`。服务端无法支持该版本时返回 `VersionNotSupportedError`。
- `A2A-Extensions`：客户端声明本次请求要使用的扩展 URI，多个以英文逗号分隔。使用 A2A-T 时，将 1.5.3 节列举的 Task-T / NEGOTIATION-T / DATA-NEGOTIATION-T 扩展 key 一并填入。若 AgentCard 中某扩展声明为 `required: true` 而客户端未在请求头声明，服务端返回 `ExtensionSupportRequiredError`。

**响应头填充规则：**

- 服务端在处理涉及扩展的请求后，在响应头 `A2A-Extensions` 中返回实际参与的扩展 URI 列表（逗号分隔），供对端确认扩展协商结果。

客户端请求头完整填充示例：

```python
import httpx

TASK_PROMPT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/Task-T/v1"
NEGO_TEXT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/NEGOTIATION-T"
NEGO_CTX_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1"

HEADERS = {
    "Content-Type": "application/json",
    "A2A-Version": "1.0",
    "A2A-Extensions": ",".join([TASK_PROMPT_EXT, NEGO_TEXT_EXT, NEGO_CTX_EXT]),
}

resp = httpx.post("https://agent.example.com/", headers=HEADERS, json=json_rpc_payload, timeout=30)
```

服务端填充响应头示例（FastAPI 注入 `Response` 后写入）：

```python
from fastapi import FastAPI, Response

NEGO_CTX_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1"
A2A_EXTENSIONS = [TASK_PROMPT_EXT, NEGO_TEXT_EXT, NEGO_CTX_EXT]

app = FastAPI()

@app.post("/")
def handle_message(payload: dict, response: Response):
    response.headers["A2A-Extensions"] = ",".join(A2A_EXTENSIONS)
    # ... 业务处理
    return {"result": "ok"}
```

### 1.5.3 携带 A2A-T 提示词发送任务

客户端先生成 processed task prompt，再将其作为 A2A 消息的一部分发送给目标 agent。A2A-T 的数据通过 A2A 消息的扩展字段携带，使用以下扩展 key：

| 扩展 key | 含义 |
|--|--|
| `https://projects.tmforum.org/a2aproject/telecommunication/extensions/Task-T/v1` | processed task prompt 文本 |
| `https://projects.tmforum.org/a2aproject/telecommunication/extensions/NEGOTIATION-T` | 协商文本 |
| `https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1` | 协商上下文 |

发送任务示例：

```python
import json

import httpx
from pathlib import Path

from a2a_t.client.a2at_client import A2ATClient

TASK_PROMPT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/Task-T/v1"
NEGO_TEXT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/NEGOTIATION-T"
NEGO_CTX_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1"

client = A2ATClient(env_path=Path("package_data/.env"))

# 1) 生成 A2A-T 提示词
result = client.generate_task_prompt(
    {
        "scenario": "subscribe_incident",
        "objective": "Subscribe to incident notifications from network devices.",
        "subscription_condition_incident_level": ["critical"],
    }
)
if not result.success:
    raise RuntimeError(result.failure.to_dict())
processed_prompt = result.prompt_text

# 2) 通过 A2A JSON-RPC 发送任务（请求头声明扩展，消息体携带 A2A-T 扩展字段）
resp = httpx.post(
    "https://agent.example.com/",
    headers={
        "Content-Type": "application/json",
        "A2A-Version": "1.0",
        "A2A-Extensions": ",".join([TASK_PROMPT_EXT, NEGO_TEXT_EXT, NEGO_CTX_EXT]),
        "Authorization": f"Bearer {AGENT_TOKEN}",   # 见 1.6 节
    },
    json={
        "jsonrpc": "2.0",
        "id": 1,
        "method": "message/send",
        "params": {
            "message": {
                "role": "user",
                "parts": [
                    {"text": "subscribe_incident task"}
                ],
                "extensions": {
                    TASK_PROMPT_EXT: processed_prompt,
                },
            },
        },
    },
    timeout=30,
)
resp.raise_for_status()
```

### 1.5.4 服务端接收并校验

服务端在 A2A 业务回调中，从消息扩展字段取出 processed task prompt，交给 `A2ATServer.check_task_prompt` 校验：

```python
from pathlib import Path

from a2a_t.negotiation.common.enums import NegotiationType
from a2a_t.negotiation.common.models import StartNegotiationInput
from a2a_t.server.a2at_server import A2ATServer

TASK_PROMPT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/Task-T/v1"

server = A2ATServer(env_path=Path("package_data/.env"))

def handle_a2at_message(message: dict) -> dict:
    processed_prompt = message["extensions"].get(TASK_PROMPT_EXT)
    if not processed_prompt:
        return {"error": "missing A2A-T task prompt"}

    check_result = server.check_task_prompt(processed_prompt_text=processed_prompt)
    if check_result["success"]:
        # 校验通过，进入业务执行
        return {"status": "accepted", "business": execute_business(processed_prompt)}

    # 校验失败，发起协商（见 1.5.5）
    return server.start_negotiation(
        StartNegotiationInput(
            type=NegotiationType.INFORMATION,
            content_text="Please provide missing subscription information.",
            facts={"failure": check_result["failure"]},
        )
    )
```

### 1.5.5 协商消息传递

协商接口返回的 `dict` 中包含协商文本与可传输的上下文，需由业务系统将两者随 A2A 消息往返传递：

```python
from a2a_t.negotiation.common.enums import NegotiationStatus, NegotiationType
from a2a_t.negotiation.common.models import ContinueNegotiationInput, NegotiationContext, StartNegotiationInput

NEGO_TEXT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/NEGOTIATION-T"
NEGO_CTX_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1"

# server / client 为 1.2.3 初始化的 A2ATServer / A2ATClient 实例
# 服务端发起协商返回：{NEGO_TEXT_EXT: 协商文本, NEGO_CTX_EXT: 上下文, [TASK_PROMPT_EXT]: 最终任务提示词}
nego_payload = server.start_negotiation(StartNegotiationInput(...))
# 业务将协商文本与上下文取出，放入 A2A 消息扩展字段返回给客户端
nego_text = nego_payload[NEGO_TEXT_EXT]
nego_ctx = nego_payload[NEGO_CTX_EXT]

# 客户端收到对端协商消息后继续推进
receive_result = client.receive_negotiation(
    message=remote_message_text,
    context=remote_context,
)
if receive_result["needResponse"]:
    continue_payload = client.continue_negotiation(
        ContinueNegotiationInput(
            context=NegotiationContext.from_context(receive_result["context"]),
            status=NegotiationStatus.IN_PROGRESS,
            content_text=processed_prompt,
        )
    )
```

> 协商上下文必须原样透传，不能拆分或重新构造；`continue_negotiation` 要求上下文与本地状态完全一致（见 `negotiation_handler.py` 的校验逻辑）。

## 1.6 接口鉴权

### 1.6.1 鉴权方案概览

A2A 协议支持多种鉴权方案，在 AgentCard 的 `securitySchemes` 中声明，客户端依据声明选择携带凭证的方式：

| 方案 | 声明类型 | 凭证位置 |
|--|--|--|
| API Key | `ApiKey` | header / query / cookie（如 `X-API-Key`） |
| HTTP Bearer | `HttpAuth`（scheme: bearer） | `Authorization: Bearer <token>` |
| OAuth2 | `OAuth2` | `Authorization: Bearer <access_token>` |
| OpenID Connect | `OpenIdConnect` | `Authorization: Bearer <id_token>` |
| mTLS | `MutualTls` | TLS 客户端证书 |

### 1.6.2 在 AgentCard 中声明鉴权

如 1.3.3 示例所示，服务端在 AgentCard 中声明支持的方案。客户端检索到 AgentCard 后，应据此构造带凭证的请求。

### 1.6.3 客户端携带凭证

```python
import httpx

TASK_PROMPT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/Task-T/v1"
NEGO_TEXT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/NEGOTIATION-T"
NEGO_CTX_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1"
A2A_T_HEADERS = {
    "Content-Type": "application/json",
    "A2A-Version": "1.0",
    "A2A-Extensions": ",".join([TASK_PROMPT_EXT, NEGO_TEXT_EXT, NEGO_CTX_EXT]),
}

# API Key 方式
resp = httpx.post(
    agent_card["url"],
    headers={**A2A_T_HEADERS, "X-API-Key": API_KEY},
    json=json_rpc_payload,
    timeout=30,
)

# Bearer Token 方式
resp = httpx.post(
    agent_card["url"],
    headers={**A2A_T_HEADERS, "Authorization": f"Bearer {ACCESS_TOKEN}"},
    json=json_rpc_payload,
    timeout=30,
)
```

### 1.6.4 服务端校验凭证

服务端在 A2A 请求进入业务处理前校验凭证，未通过返回 HTTP `401 Unauthorized`。以 FastAPI 为例：

```python
from fastapi import Header, HTTPException

API_KEYS = {"allowed-key-1", "allowed-key-2"}  # 应由密钥管理系统下发，勿硬编码

def require_auth(x_api_key: str | None = Header(default=None)) -> None:
    if x_api_key not in API_KEYS:
        raise HTTPException(status_code=401, detail="unauthorized")
```

### 1.6.5 安全建议

1. 生产环境必须启用 HTTPS，避免凭证在传输中被窃取。
2. 密钥/证书交由密钥管理系统（如 KMS、Vault）管理，不硬编码在代码或配置中。
3. Bearer Token 应设置有效期并支持撤销；API Key 应支持轮换。
4. 对本 SDK 依赖的 LLM 凭证（`A2AT_LLM_API_KEY`）与 agent 间通信凭证分开管理。

## 1.7 完整集成示例

### 1.7.1 服务端 Agent（FastAPI + A2ATServer）

```python
from pathlib import Path

from fastapi import Depends, FastAPI, Header, HTTPException, Response

from a2a_t.negotiation.common.enums import NegotiationType
from a2a_t.negotiation.common.models import StartNegotiationInput
from a2a_t.server.a2at_server import A2ATServer

TASK_PROMPT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/Task-T/v1"
NEGO_TEXT_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/NEGOTIATION-T"
NEGO_CTX_EXT = "https://projects.tmforum.org/a2aproject/telecommunication/extensions/DATA-NEGOTIATION-T/v1"
A2A_EXTENSIONS = [TASK_PROMPT_EXT, NEGO_TEXT_EXT, NEGO_CTX_EXT]
API_KEYS = {"allowed-key-1"}

app = FastAPI()
server = A2ATServer(env_path=Path("package_data/.env"))

def require_auth(x_api_key: str | None = Header(default=None)) -> None:
    if x_api_key not in API_KEYS:
        raise HTTPException(status_code=401, detail="unauthorized")

@app.post("/")
def handle_message(
    payload: dict,
    response: Response,
    _: None = Depends(require_auth),
    a2a_version: str | None = Header(default=None),
):
    # 响应头声明实际参与的 A2A-T 扩展
    response.headers["A2A-Extensions"] = ",".join(A2A_EXTENSIONS)

    if a2a_version != "1.0":
        raise HTTPException(status_code=400, detail="unsupported A2A version")

    message = payload["params"]["message"]
    processed_prompt = message.get("extensions", {}).get(TASK_PROMPT_EXT)
    if not processed_prompt:
        return {"error": "missing A2A-T task prompt"}

    check_result = server.check_task_prompt(processed_prompt_text=processed_prompt)
    if check_result["success"]:
        return {"result": execute_business(processed_prompt)}

    return server.start_negotiation(
        StartNegotiationInput(
            type=NegotiationType.INFORMATION,
            content_text="Please provide missing subscription information.",
            facts={"failure": check_result["failure"]},
        )
    )
```
